# Трасса запроса

1. Начать со справочника области — там цепочка уже может быть; код открывать для уточнения шага.
2. Таблица: `| Переход | Протокол/порт | Путь или метод | Файл | Преобразование данных |`.
   Обязательно отмечать смены формата (JSON snake_case ↔ DTO ↔ proto ↔ XML и т. п.): большинство багов
   живёт на этих швах — переименованные поля, потерянные необязательные значения, часовые пояса.
3. Асинхронные ответвления: очереди, колбэки, фоновые задачи, кэши — где состояние меняется вне запроса.
4. Для «где ломается»: идти по переходам сверху вниз и для каждого назвать способ проверить именно его
   (тест, прямой вызов слоя, лог). Ошибочный путь — `/error-trace`.
5. Нетривиальную трассу — в справочник области (`/update-refs`).
