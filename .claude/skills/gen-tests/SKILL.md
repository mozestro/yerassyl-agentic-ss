# Минимальные тесты

1. **Эталон**: найти в проекте ближайший тест того же типа (сервис, конвертер, контроллер) и повторить его
   устройство: моки, фикстуры, хелперы. Не изобретать новый стиль.
2. **Сколько**: один тест на новое поведение. Не писать тесты на проброс одного поля и дубли сценария на
   разных слоях. Ветки проверок входа — одним компактным или параметризованным тестом по чистой функции.
3. **Обязательно**: ошибка внешнего вызова → правильный код и статус; каждый новый код ответа внешней системы;
   переход в неверном состоянии.
4. **Моки ошибок** — тем типом исключения, который реально бросает клиент, а не удобным: неверный тип прячет баги.
5. **Прогон**: форматирование → тесты → покрытие нового кода (`/coverage-gap`). Тест упал на реальном
   поведении — доложить, не подгонять тест под баг.
