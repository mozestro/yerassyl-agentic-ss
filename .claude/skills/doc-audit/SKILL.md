# Аудит по документации

Результат — отчёт, а не починка. Правки — только если человек попросил.

## Порядок

1. **Все источники требований**: оригиналы (вики, спецификации, вложения — читать целиком, в хвостах бывают
   приложения с контрактами), локальные выгрузки (сверить свежесть), справочник модуля.
   Бинарные вложения (`.doc/.docx/.pdf`) — сконвертировать в текст во временную папку и искать по таблицам.
2. **Список требований**: эндпоинты, обязательность полей, маппинги, коды ошибок и HTTP-статусы, статусы,
   схемы данных (сверять с официальной схемой владельца, не с пересказом), валидации, последовательность шагов.
3. **Сверка с кодом**: каждый пункт → `файл:строка`. Сборка и тесты — фактическое состояние.
4. **Классификация**: пропущено (с критичностью) / лишнее / противоречия документов (не решать самому —
   вопрос аналитику) / гигиена перед коммитом.
5. **Отчёт**: что в порядке (кратко) → пропущено → лишнее → вопросы аналитику (`/analyst-msg`) → гигиена.
   Каждый пункт со ссылкой и цитатой.

git add/commit не выполнять.
