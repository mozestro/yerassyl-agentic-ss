# Передача в QA

## Содержимое тест-кейсов

1. **Шапка**: версии всех затронутых модулей, стенд, тестовые данные (не выдумывать: неизвестное —
   плейсхолдер и вопрос человеку), ссылка на спецификацию API.
2. **Авторизация**: команда получения токена (без значений секретов), сколько живёт.
3. **Кейсы** через публичный вход системы — по одному на поведение: успешный путь по шагам; каждая валидация
   (код и текст ошибки из кода, не из документа); без авторизации; чужие данные; финальный результат
   (что должно быть в файле/ответе). Каждый — заголовок, «Ожидается: …», команда.
4. **Разделение по задачам**: полный набор — в задаче публичного слоя, в остальных — кейсы своего слоя и ссылка.
5. **Последняя строка — честно**: «Проверено на стенде DD.MM: кейсы …, идентификатор …» или «Ещё не
   проверялось: ждём …».

## Грабли

- Интеграции с трекером могут конвертировать текст (markdown → wiki) и экранировать символы внутри блоков кода,
  после чего команды не копируются. После записи перечитать поле; если испорчено — писать через REST API трекера
  напрямую, токен из локального конфига, не выводить.
- Обязательные поля перед переходом статуса — узнать заранее по уже переведённой задаче.
