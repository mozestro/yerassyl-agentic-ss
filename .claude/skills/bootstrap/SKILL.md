# Первичная настройка проекта

Цель — один полный проход по проекту, после которого следующие сессии читают справочники, а не код.

## Порядок

1. **Карта.** Перечислить модули/репозитории: язык, сборка, точка входа, зависимости между ними. Для
   воркспейса из нескольких репозиториев — таблица «репозиторий → за что отвечает → ветка по умолчанию».
2. **Сборка и тесты.** Найти и выполнить команды сборки и тестов каждого модуля, записать реальный результат
   (сколько тестов, что упало и почему: среда или код). Порог покрытия CI — откуда берётся.
3. **Конфиг и стенды.** Где конфиг по окружениям, какие переменные, где секреты (только где, без значений).
4. **CI.** Этапы пайплайна, требования к имени ветки, версии, что чаще всего ломает CI.
5. **Записать:**
   - `docs/reference/ARCHITECTURE.md` по шаблону `docs/templates/AREA.md` — карта, цепочки, команды;
   - раздел «Проект» в `CLAUDE.md` — один абзац;
   - строки в таблицу справочников `CLAUDE.md`;
   - `HANDOFF.md` — раздел «Состояние» с текущими ветками и контрольными числами.
6. **Спросить человека** про стоп-правила проекта: что агенту запрещено (git, стенды, внешние системы),
   кто ревьюит, где трекер. Ответы — в `CLAUDE.md` и память.

Не править код во время bootstrap. git add/commit не выполнять.
