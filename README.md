# yerassyl-agentic-ss

Шаблон рабочего окружения для разработки с ИИ-агентом (Claude Code). Не зависит от языка и проекта: копируется
в любой репозиторий или воркспейс из нескольких репозиториев и даёт агенту память между сессиями, правила
поведения и набор проверенных процедур.

Структура выросла из реальной работы над крупным проектом из десятков микросервисов: несколько месяцев
ежедневных сессий, сотни задач. Здесь только то, что пережило эту практику.

## Идея

Контекст сессии агента умирает, файлы остаются. Поэтому всё, что агент узнал дорогой ценой, ложится на диск
в одно определённое место, а следующая сессия начинает с чтения этих файлов, а не со сканирования кода заново.

| Слой | Где | Что хранит | Как часто меняется |
|---|---|---|---|
| Правила | `CLAUDE.md` | стоп-правила, стиль, карта справочников | редко |
| Состояние | `HANDOFF.md` | незакрытые нити, ветки, чего ждём | каждую сессию |
| Знание | `docs/reference/*.md` | как устроено, грабли, «почему так» | по мере работы |
| Процедуры | `.claude/skills/*/SKILL.md` | повторяемые порядки действий | когда что-то сделали дважды |
| Инструменты | `tools/` | скрипты, генераторы, проверялки | когда скрипт понадобился второй раз |
| Память агента | `~/.claude/projects/<проект>/memory/` | предпочтения, договорённости, указатели | по ходу |

## Как применить к новому проекту

1. Скопировать `CLAUDE.md`, `HANDOFF.md`, `docs/`, `tools/`, `.claude/skills/` в корень проекта.
2. В `CLAUDE.md` заполнить раздел «Проект» и стоп-правила под себя, остальное оставить.
3. Попросить агента выполнить `/bootstrap`: он просканирует проект один раз и заведёт первые справочники и
   строки индекса.
4. Дальше работать как обычно, в конце значимой сессии — `/handoff`.

## Структура

```
CLAUDE.md                  правила агента и индекс справочников (грузится каждую сессию)
HANDOFF.md                 передаточный файл между сессиями
docs/
  WORKFLOW.md              цикл работы: начало сессии → работа → проверка → конец
  PRINCIPLES.md            правила поведения агента и откуда они взялись
  REFERENCE_GUIDE.md       как писать справочники, чтобы они не сгнили
  MEMORY_GUIDE.md          авто-память Claude Code: что туда класть, что нет
  SKILLS_GUIDE.md          когда и как заводить скилл
  templates/               шаблоны справочников
  reference/               справочники проекта (пусто, наполняется по ходу)
  archive/                 журналы и разборы «почему так было»
  personal/                личное: самооценка, цели, заметки (по желанию)
tools/                     локальная библиотека скриптов
.claude/skills/            скиллы (процедуры)
```

## Главное в двух строках

Справочник — это текущее состояние, а не дневник. Агент ничего не утверждает без проверки и не трогает git,
инфраструктуру и чужие документы без явной просьбы.
