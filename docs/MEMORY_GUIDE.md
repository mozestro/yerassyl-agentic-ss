# Память агента

Claude Code ведёт файловую память проекта (`~/.claude/projects/<проект>/memory/`): по одному факту в файле
и индекс `MEMORY.md`, который загружается в каждую сессию. Память живёт вне репозитория и не видна коллегам.

## Типы

| Тип | Что | Пример |
|---|---|---|
| `user` | кто человек, опыт, цели | «первая позиция мидла, сильный бэкенд, учит Go» |
| `feedback` | как работать: исправления и подтверждённые подходы, с причиной | «не писать тест на проброс поля» |
| `project` | текущая работа, сроки, ожидания с датами | «к 23.11 демо на stage» |
| `reference` | где что лежит: адреса, трекер, доступы (без паролей) | «доска команды, поле спринта» |

## Правила

- **Указатель, а не копия.** Если факт есть в репозитории (справочник, код), в памяти — ссылка на файл и одна
  строка, зачем туда смотреть. Дубль содержимого — ужать до указателя.
- **Feedback с причиной.** Формат: правило → `Why:` (что случилось, дата) → `How to apply:`. Без причины правило
  выглядит произвольным и нарушается в пограничном случае.
- **Не хранить** то, что уже есть в коде, git-истории или `CLAUDE.md`, и то, что нужно только в текущей сессии.
- **Обновлять, а не плодить.** Перед новой записью — найти существующую по теме.
- **Удалять неверное.** Устаревшая запись в памяти обманывает каждую следующую сессию.
- **Личное — отдельно.** Заметки о себе, целях, самооценке — в `docs/personal/` (если репозиторий приватный)
  или в памяти; в общие справочники не попадают.

## Что из памяти стоит перенести в репозиторий

Если правило касается не человека, а проекта (как собирать, как деплоить, грабли сервиса) — это справочник,
а не память: его должны видеть и другие люди, и другие агенты.
