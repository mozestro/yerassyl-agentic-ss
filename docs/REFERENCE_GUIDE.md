# Как писать справочники

Справочник — выжимка для следующей сессии агента: как устроено, где грабли, почему так решили. Хороший
справочник позволяет продолжить работу, не открывая код. Устаревший справочник вреднее отсутствующего.

## Правила

1. **Текущее состояние, не дневник.** Нельзя дописывать в хвост «— 21.09: теперь иначе». Найти место, где
   факт описан, переписать его; старое неверное удалить.
2. **Объём ~1k токенов на область.** Детали живут в коде; справочник отвечает на «где» и «почему».
3. **Ссылки вместо копий.** Путь к файлу, имя класса, команда — да; копия кода — нет.
4. **Проверенное отдельно от предположений.** Непроверенное помечать прямо: «не проверено», «со слов».
5. **Даты абсолютные.** «Вчера» через месяц ничего не значит.
6. **История — в архив.** Длинный разбор «почему было так» — `docs/archive/<ОБЛАСТЬ>_JOURNAL.md`, в справочнике
   одна строка в таблице «Не переделывать».
7. **Индекс.** Новый справочник — строка в таблицу `CLAUDE.md` с ответом «когда читать» одной фразой.

## Что куда

| Тип факта | Место |
|---|---|
| Как устроено, команды, грабли | справочник области |
| Почему решили так, а не иначе | таблица «Не переделывать» в справочнике |
| Незакрытые нити, ветки, ожидания | `HANDOFF.md` |
| Предпочтения человека, договорённости | память агента |
| Выгрузки чужих документов (требования) | `docs/<область>/` с датой выгрузки; источник правды — оригинал |

## Самопроверка

«Сможет ли следующая сессия по одним справочникам продолжить, не сканируя код?» Если нужного факта нигде
нет — он потеряется, добавить.

Шаблон — `docs/templates/AREA.md`.
