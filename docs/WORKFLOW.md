# Цикл работы с агентом

## Начало сессии

1. Агент читает `CLAUDE.md` (автоматически) и `HANDOFF.md`.
2. По задаче открывает один справочник из индекса, а не весь проект. Справочник — выжимка на ~1k токенов,
   он экономит десятки вызовов поиска по коду.
3. Если справочника по области нет, а задача в ней не первая — после задачи он появляется (`/update-refs`).

## Работа

- **Задача → самый узкий слой.** Сначала понять, где живёт поведение (`/flow-trace`), потом править там.
- **Внешние библиотеки — по исходникам.** Поведение метода не угадывается по названию: распаковать sources и
  прочитать (`/lib-dig`). Найденное — в справочник, чтобы не копать второй раз.
- **Требования — сначала документы, потом чаты.** Документ — источник правды, переписка — уточнения. Свежий
  документ перекрывает старое сообщение.
- **Проверка на стенде** — реальным запросом, с честным отчётом: что прошло, что упало, на каком шаге.
- **Временные файлы** — во временную папку агента. Всё, что понадобилось дважды (скрипт, генератор, пример
  данных), переезжает в `tools/` проекта: временную папку чистят.

## Проверка перед «готово»

1. Сборка и тесты зелёные, числа в ответе («1669 тестов, 0 упавших»).
2. Покрытие нового кода — по тому же правилу, что в CI (`/coverage-gap`).
3. Дифф хирургический: только строки задачи.
4. Перед пушем — `/pre-push`: временные версии, мусор в индексе, форматирование.

## Отчёт человеку

- Первая строка — итог: сделано / не сделано / заблокировано чем.
- Дальше — только то, что нужно для решения или следующего шага. Без пересказа процесса.
- Непроверенное помечается как непроверенное.
- Сообщение коммита предлагается текстом; коммитит человек.

## Конец значимой сессии

`/handoff`: новое знание — в справочники, причины решений — в «Не переделывать», нити — в `HANDOFF.md`,
договорённости — в память. Цель: следующая сессия продолжает по одним файлам, не сканируя код.

## Задачи в трекере

- Тексты нейтральные: что сделать, без имён авторов и поиска виноватых.
- Тест-кейсы для QA — с готовыми командами (curl и т. п.), ожидаемым результатом и честной строкой
  «проверено на стенде DD.MM» или «ещё не проверялось» (`/qa-handoff`).
